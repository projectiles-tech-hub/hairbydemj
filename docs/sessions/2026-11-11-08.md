# Session 2026-11-11-08

## What was done

- Owner asked whether showing exact stock is better, and to move on. The
  shop now shows the exact number that can be bought (added to pull request
  #13).
- Module 5 (Media) built on `feature/media`, on top of modules 2 to 4:
  - Upload address for staff; the file is the request body, saved to disk as
    it arrives, with size limits; who is asking is checked first.
  - Files recognised by their first bytes; scripts, web pages and SVG refused.
  - Photos: five widths in WebP and JPEG with libvips, never enlarged,
    turned upright, hidden details removed.
  - Videos: MP4 (H.264, AAC, at most 1280 pixels) with a poster picture, by
    ffmpeg, in the background; picked up again after a restart.
  - Files served under `/media/` on all addresses with a year-long cache and
    partial requests; the untouched uploads are kept where they cannot be fetched.
  - Order, description and colour per photo; removal deletes the files.
  - The catalogue now gives each photo's sizes and leaves out anything not ready.
- Checks: 136 tests pass against PostgreSQL 16 with libvips 8.15 and ffmpeg
  6.1 (71 run without a database). GitHub Actions installs both tools.
- Guide written: `docs/media.md`.

## Decisions made

- Exact stock is shown to customers (owner).
- Upload is the raw file as the request body, not a form: simpler and needs
  no form-parsing code.
- Sizes 320, 640, 960, 1280, 1920; limits 25 MB per photo, 300 MB and 2
  minutes per video, 10 photos and 1 video per product (the last from the
  approved product editor).
- Photos link to variants by colour.
