# Session 2026-11-11-10

## What was done

- Module 7 (Payments) built on `feature/payments`, on top of modules 2 to 6:
  Paystack and Stripe clients over REST, payment start with reuse, webhook
  signature checks, one-time recording of webhooks, confirmation only with
  the exact amount, failure handling, late payments after an expired
  checkout, refunds (partial and full) with provider confirmation, admin
  addresses for providers, payouts and refunds.
- Paystack's refund webhook fields were checked against Paystack's own
  documentation (https://paystack.com/docs/payments/refunds/): refunds are
  matched by the payment's reference and amount, as the webhook carries no
  refund id.
- Checks: 168 tests pass against PostgreSQL 16, with stand-in providers.

## Decisions made

- Stripe payments use a PaymentIntent (works for the website's payment
  form and the app's payment sheet); Paystack uses its hosted payment page
  or access code.
- Paid status comes only from webhooks, as the plan says; the return page
  polls our own status address meanwhile.
- A payment after an expired checkout revives the order if stock allows,
  or is refunded automatically.
